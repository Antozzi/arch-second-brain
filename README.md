# Second Brain

Персональный AI-ассистент архитектора — работает локально, данные не покидают машину.

> **Первый запуск?** → [INSTALLATION.md](INSTALLATION.md) — установка зависимостей, настройка  
> **Запуск, логи, диагностика?** → [DEPLOYMENT.md](DEPLOYMENT.md) — тестовый прогон, мониторинг, решение проблем

---

## Запуск

```bash
./start.sh
```

Открой в браузере: **http://localhost:3030**

Ollama запускается автоматически если не запущена.

## Как работать с новым проектом

### 1. Получил задачу в Jira

Запомни номер тикета — например `ARCH-123`. Это твой ключ для всей работы с проектом.

---

### 2. Загрузи материалы

Открой **⊕ Загрузить проект** в UI.

Введи Jira тикет и путь к папке с документами проекта. Нажми **① Загрузить и конвертировать** — система разберётся с форматами: PDF, Word, Excel, PowerPoint, изображения, диаграммы.

Во время загрузки доступна кнопка **■ Стоп** для прерывания.

---

### 3. Настрой скилл проекта

После загрузки появляется карточка **② Скилл проекта**.

Нажми **⇒ Проанализировать** — модель изучит документы и предложит инструкцию извлечения знаний (`ARCH-123-SKILL.md`). Отредактируй при необходимости и нажми **✓ Сохранить**.

Без скилла используется дефолтный SA-промпт. Скилл можно пропустить кнопкой **Пропустить шаг**.

---

### 4. Обработай через модель

Нажми **③ Запустить обработку** — локальная модель прочитает документы и разложит знания по категориям.

Большие документы обрабатываются **чанками с полным покрытием** — файл режется на куски по `MAX_CHARS`, каждый идёт через модель, результаты сливаются. Ничего не теряется, но прогон больших проектов может занять часы.

Во время обработки доступны:
- **■ Стоп** — прервать всё
- **⇥ Пропустить файл** — пропустить текущий файл и продолжить

Размер чанка вычисляется автоматически по объёму ОЗУ и размеру модели (можно переопределить в Настройках → MAX_CHARS).

> Если документы на русском — после загрузки система предложит установить модель **qwen2.5** (точнее с кириллицей). Можно поставить в один клик прямо в потоке Ingest.

---

### 5. Проверь что загрузилось

Открой **⚠ Пропущенные файлы** и выбери свой проект.

Если файлы не прочитались (сканы PDF, битая кодировка) — система покажет их. Нажми **⇪ Заменить** и загрузи читабельную версию. Потом отметь галочкой и нажми **Переобработать**.

---

### 6. Спроси модель

Открой **◎ Спросить модель**.

Выбери один или несколько проектов кликом по чипам — контексты объединятся. Задавай вопросы на русском:

- *Какие риски интеграции выявлены?*
- *Кто стейкхолдеры и каковы их интересы?*
- *Какие архитектурные решения уже приняты?*
- *Что осталось без ответа?*

Для глубокого анализа используй **✦ Claude API** — запрос уйдёт в облако через более мощную модель.

---

### 7. Генерируй черновики артефактов

Открой **◈ Генерация артефакта**.

Три режима через переключатель вверху:

- **📄 Текстовый раздел** — выбери тип документа (HLD, HLIS, AN, SPFA, BRD), загрузи свой шаблон или сгенерируй новый в разделе **◇ Шаблоны**, выбери раздел и нажми **Ollama** или **✦ Claude API**. Модель заполнит раздел знаниями из выбранных проектов — скопируй результат в Confluence.
- **◫ PlantUML диаграмма** — выбери тип (sequence, component, C4, deployment, activity, ER, state, class, mindmap и др.), опиши что изобразить и нажми **Ollama** или **✦ Claude API**. Модель построит диаграмму из базы знаний — справа живое превью, код PlantUML можно отредактировать и обновить (**↻**), готовую диаграмму — скачать в SVG.
- **⬚ drawio диаграмма** — модель строит схему из знаний и собирает валидный drawio XML с превью. Готовую диаграмму можно **экспортировать** в `.drawio` или **сохранить в проект**. Любую существующую `.drawio` можно **импортировать** — её объекты попадают в *каталог объектов проекта* и переиспользуются в новых диаграммах (одинаковые названия и стили), а содержимое уходит в базу знаний при обработке.

---

### 8. Прокачай модель скиллами

Скиллы — это инструкции для модели по извлечению знаний из конкретного домена.

**Скилл проекта** (`② Скилл проекта` в потоке Ingest):
- Создаётся под конкретный проект → `knowledge/projects/ARCH-123/ARCH-123-SKILL.md`
- Можно применить к проекту существующий глобальный скилл
- Можно **↑ Сделать глобальным** — скилл скопируется в `skills/` и станет доступен всем проектам

**Глобальные скиллы** (`◆ Скиллы` в меню):
- **Из базы знаний проекта** — модель извлекает предметную экспертизу домена
- **Из PDF книги** — подходит для методологий, фреймворков, вендорской документации
- Встроенный скилл `knowledge-processor` (CLAUDE.md) всегда виден как read-only

---

### 9. Появились новые материалы

Повтори шаги 2–4 для новой папки или файлов. Уже обработанные документы система пропустит автоматически.

---

### 10. Сохрани базу знаний

```bash
git add knowledge/ templates/ scripts/ skills/ CLAUDE.md
git commit -m "ARCH-123: обновление базы знаний"
git push
```

Сырые материалы (`raw/`) и API ключи (`.env`) в git не попадают — только структурированные знания.

## Что система знает о проекте

После обработки документов база знаний содержит:

- **Бизнес-контекст** — проблема, цели, границы, стейкхолдеры
- **Требования** — функциональные, NFR, безопасность
- **Архитектура** — AS-IS, TO-BE, интеграции, сценарии
- **Решения** — ADR с обоснованием и отклонёнными альтернативами
- **Риски** — с оценкой влияния и мерами митигации
- **Открытые вопросы** — что ещё не решено
- **Стейкхолдеры** — роли, интересы, RACI

Каждое утверждение трассируется до источника. Если источника нет — помечается `#hypothesis`.

---

## Что никогда не уходит в облако

Реальные имена людей, названия компаний-клиентов, коммерческие условия, сырые рабочие документы — всё это остаётся только локально. В Claude API отправляется только обезличенный контент из `knowledge/`.

## Дополнительно

- Просмотр связей между проектами → открой vault в **Obsidian** (`open ~/projects/second-brain`)
- Управление проектами → кнопка **✕** рядом с проектом в левой панели удаляет его из базы
- Смена локальной модели → **⚙ Настройки** → Ollama модель (список подтягивается из Ollama автоматически)
- Смена Claude модели или API ключа → **⚙ Настройки** (ключ опционален — без него Claude API недоступен, но локальная модель работает)
- Просмотр бюджета Claude API → **⚙ Настройки** → ссылка на Anthropic Console
- Ручная настройка лимита токенов → **⚙ Настройки** → поле **MAX_CHARS** (пусто = авто по ОЗУ и модели)
- Догрузить новые материалы → **⊕ Загрузить проект** → тот же тикет, новый путь
- Остановить обработку → кнопка **■ Стоп** во время Ingest или Process
- Пропустить текущий файл → кнопка **⇥ Пропустить файл** во время Process
- Сохранить ответ Claude API в базу знаний → кнопка **⊕ Сохранить в знания** под ответом
- Просмотреть или удалить глобальный скилл → **◆ Скиллы** → кнопка 👁 / ✕
- Создать шаблон артефакта → **◇ Шаблоны** → из структуры документа или по ИТ-стандарту (TOGAF/BABOK/PMBOK/ISO)
- Спросить по нескольким проектам → **◎ Спросить модель** → кликни нужные чипы проектов
- Генерировать артефакт по нескольким проектам → **◈ Генерация артефакта** → выбери чипы проектов
