# SKILL: siem-logging-dbss

## DESCRIPTION
Обеспечение логирования DBSS в SIEM с использованием bridging solutions и соблюдением архитектурных принципов.

## WHEN_TO_USE
- При необходимости интеграции DBSS с SIEM.
- При разработке bridging solutions для логирования.
- При необходимости документирования архитектурных решений, связанных с логированием.

## CORE_CONCEPTS
- **SIEM logging**: Сбор и анализ логов для обеспечения безопасности и соответствия требованиям.
- **DBSS**:  Компонент системы, требующий логирования.
- **Bridging solution**: Решение для интеграции компонентов, обеспечивающее логирование.
- **Requirement Yogi**: Инструмент для управления требованиями.
- **Component registry**: Реестр компонентов системы.
- **Architecture Decision**: Зафиксированное архитектурное решение.
- **IDD (Integration Design Document)**: Документ, содержащий детальное описание интеграции.

## DECISION_RULES
- Если необходимо двигаться вперед при неопределенности → создайте Assumption.
- Если стороны согласны исключить что-то из обсуждения/архитектуры/объема → запишите это в таблицу Exclusions.
- Если есть деталь, влияющая на решение, но не под контролем сторон → добавьте ее в таблицу Restrictions.
- При создании Bridging solution → используйте Requirement Yogi (Alt+Shift+R).
- Если что-то необходимо для корректной работы компонента на любой фазе → это должно быть указано в таблице Identified requirements.
- Если requirement требует более подробной информации → предоставьте ее в IDD.

## PLAYBOOKS
### Создание Bridging Solution
1. Создайте уникальный идентификатор Bridging solution с помощью Requirement Yogi.
2. Опишите, как планируется реализовать bridging.
3. Укажите компоненты, к которым применимо решение, используя Component registry.
4. Определите фазы, для которых предназначено решение (TP, Prepaid, Postpaid или комбинация).
5. Укажите фазу, в которой решение должно быть выведено из эксплуатации.

## ANTI_PATTERNS
- ❌ Не создавайте Bridging solution без уникального идентификатора: Это приведет к путанице и затруднит отслеживание.
- ❌ Не используйте названия компонентов, не взятые из Component registry: Это нарушит целостность системы и может привести к ошибкам.
- ❌ Не делайте Assumption, если есть четкое понимание ситуации:  Assumption должны использоваться только в случае неопределенности.
