# Architecture Decision Records — ARCH-PULSE-AI

## ADR-001 Выбор Orchestrator на основе Kubernetes
- **Status**: Accepted
- **Context**: Необходимость масштабируемости и отказоустойчивости.
- **Decision**: Использовать Kubernetes для оркестровки AI-сервисов.
- **Alternatives**: Использование монолитного решения.
- **Consequences**: Повышенная гибкость и масштабируемость, но требуется экспертиза Kubernetes.

## ADR-001 Выбор платформы оркестрации
- **Status**: Proposed
- **Context**: Необходимость выбора платформы для оркестрации AI-сервисов.
- **Decision**: Предлагается использовать Kubernetes для оркестрации.
- **Alternatives**: Рассматривались другие платформы, но Kubernetes показался наиболее подходящим.
- **Consequences**: Повышение гибкости и масштабируемости AI-решений.

## ADR-001 Определение статуса вопросов к команде вендора
- **Status**: Proposed
- **Context**: Необходимость определения статуса каждого вопроса для отслеживания прогресса.
- **Decision**: Предлагается использовать систему отслеживания вопросов с указанием статуса (например, 'Открыт', 'В работе', 'Решен').
- **Alternatives**: Использование электронной почты для отслеживания вопросов.
- **Consequences**: Более эффективное управление вопросами и повышение прозрачности процесса.
- **Source**: [[2026-05-04-questions-to-the-veon-vendor-team-1]]
